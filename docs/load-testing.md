# اختبار ضغط فطنة 1.3

هذا الاختبار مخصص لنسخة **staging منشورة منفصلة**. لا تشغّله على `ata20.com`
أو على نسخة App Store. لا يحتوي المشروع عنواناً افتراضياً حتى لا يبدأ ضغطاً
بالخطأ على خدمة حقيقية.

## الخطة دون شبكة

```sh
npm run loadtest:plan
```

المراحل الافتراضية: 100 ثم 300 ثم 500 ثم 1000 لاعب افتراضي. المدد خمس، خمس،
عشر، عشر دقائق، وبين المراحل الناجحة دقيقتان للتهدئة. يتوقف التصعيد تلقائياً
إذا تجاوزت الأخطاء 5% أو تجاوز `p95` ثلاث ثوانٍ.

## تشغيل staging

```sh
FATINAH_LOAD_TEST_URL=https://YOUR-STAGING.replit.app \
FATINAH_LOAD_TEST_APPROVED=staging:YOUR-STAGING.replit.app \
npm run loadtest:staging
```

لجولة سريعة قبل الاختبار الكامل يمكن ضبط
`FATINAH_LOAD_TEST_DURATION_SCALE=0.05`. لا تُحفظ رموز Firebase أو App Check
في المستودع. السيناريو الحالي يقيس بوابة API وAutoscale فقط؛ اختبار مسار الجولة
المحمية يتم بحسابات اختبار مستقلة حقيقية ولا يُضاف له مسار خلفي أو تجاوز أمني.

## المراقبة

أثناء الاختبار تُراقب لوحة Replit Monitoring لعدد النسخ، CPU، RAM، زمن
الاستجابة والأخطاء، وتُراقب Firestore للقراءات والكتابات. النجاح النهائي يتطلب
أخطاء أقل من 1% و`p95` أقل من ثانية لمسار البنك، ولا يُعتمد رقم اللاعبين من
اختبار بوابة API وحده.
