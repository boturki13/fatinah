لا تضف Node.js أو Express أو أي سيرفر منفصل، ولا MongoDB أو PostgreSQL أو
ملفات JSON لتخزين المستخدمين. كل شي يصير داخل نفس سيرفر Python الحالي
وقاعدة subscriptions.db (SQLite) الموجودة، باستخدام جدولي promo_codes
و promo_redemptions الموجودين فعلًا.

الخطوة الأولى: افحص الكود الحالي وقلي بالضبط:
1. هل فيه endpoint حالي لإنشاء كود ترويجي (إدخال نص الكود + عدد أيام
   الهدية + عدد مرات الاستخدام المسموحة)؟ إذا موجود، وش مساره وشكل
   الـ request/response بالضبط؟
2. هل فيه endpoint حالي يستدعيه التطبيق لتفعيل كود (يستقبل code + uid)؟
   وش مساره وشكل الـ request/response بالضبط؟ وهل فعليًا يحدّث جدول
   subscriptions (تاريخ انتهاء الاشتراك) لما ينجح، أو يحدّث promo_redemptions
   بس بدون ما يأثر على حالة الاشتراك الفعلية؟
3. هل فيه endpoint أو منطق حالي يتحقق من حالة اشتراك المستخدم (uid) ويرجع
   هل هو "مفعّل" الآن أو لا؟ نفس الـ endpoint اللي يستخدمه التطبيق أصلًا
   لمشتركي Stripe.

بعد الفحص، تأكد إن السلوك النهائي يطابق هذا بالضبط (كمّل الناقص فقط،
ولا تعيد كتابة الشغال أصلًا):

- إنشاء كود (محمي بصلاحية أدمن فقط، مو من داخل التطبيق): يستقبل نص الكود
  (أنا أختاره بنفسي، مثل "NR5")، عدد أيام الهدية (rewardDays)، وعدد مرات
  الاستخدام المسموحة (maxUses، افتراضي 1). يُخزَّن في promo_codes.

- تفعيل كود (يستدعيها التطبيق، يحتاج uid المستخدم المسجل دخول): يتحقق
  الكود موجود، مفعّل (مو معطّل)، وعدد استخداماته ما وصل الحد الأقصى.
  لو صحيح: يمدد تاريخ انتهاء الاشتراك في جدول subscriptions بعدد الأيام
  (rewardDays)، بحيث يمدد من "الأبعد" بين (الآن) و(تاريخ انتهاء اشتراكه
  الحالي لو أصلًا مشترك)، ويسجل الاستخدام في promo_redemptions مع الوقت
  وتاريخ الانتهاء الجديد. لو فشل يرجع سبب واضح (كود غير موجود / معطّل /
  تم استخدامه من قبل).

- مهم جدًا: النتيجة النهائية لازم تجعل حالة هذا المستخدم "مشترك فعّال"
  عبر نفس الحقل/المنطق اللي يتحقق منه التطبيق أصلًا لمشتركي Stripe —
  ما أبي حقل "active" منفصل يحتاج التطبيق يتحقق منه بطريقة ثانية. لو
  فيه مزامنة مع Firestore (subscription_outbox) تأكد تفعيل الكود يمر
  بنفس آلية المزامنة هذي زي أي تحديث اشتراك ثاني.

بعد التنفيذ: اختبر بنفسك (أنشئ كود تجريبي، فعّله لمستخدم تجريبي، تأكد
التطبيق يعتبره مشترك فعّال، وتأكد إعادة استخدام نفس الكود تفشل بسبب واضح)،
وقلي في ردك: مسار endpoint الإنشاء، ومسار endpoint التفعيل، وشكل الـ
request/response بالضبط لكل واحد، عشان أربط ملف الواجهة (apple-redeem.js)
فيهم بدقة.
